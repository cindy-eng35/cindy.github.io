03 / METHODOLOGY

A transparent analysis workflow.

Defined metrics and repeatable comparisons — not black-box conclusions.

At least 3 analyses
01 · INGESTRetrieve and verify

Use official 2017 schema and document the chosen trace.

02 · CLEANValidate records

Check timestamps, identifiers, missingness and ranges.

03 · ANALYZEQuantify & compare

CPU, memory, correlations and load categories.

04 · EXPLAINInterpret with OS theory

Discuss resource allocation, scheduling and limitations.

ANALYSIS 01

CPU utilization

Histogram of CPU utilization (%), mean load by observed interval, and comparison between high-usage, low-usage and variable machines.

ANALYSIS 02

Memory & correlation

Memory distribution and CPU-versus-memory scatter plot, paired observations, and correlation with discussion of mismatches.

ANALYSIS 03

Resource imbalance

Classify utilization with documented cutoffs, compare machines and examine category changes over time and possible scheduling consequences.

PROPOSED THRESHOLDS — ADJUSTABLE

Low / medium / high

Low: <30% Medium: 30–70% High: >70%

These thresholds are an analysis proposal, not a standard imposed by Alibaba or the instructor. The team must justify the chosen cutoffs and report their limitations.

TOOLS & REPRODUCIBILITY

Python + GitHub Pages

The provided Python analysis script can generate labeled figures from actual records. Site assets, selected data procedure, versioned code and dependencies should be published so others can reproduce the comparisons.
